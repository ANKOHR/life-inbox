# Lessons for KOML

This domain needs a reliable capture schema and visible triage rules before it needs automation. Tasks require an explicit reference date; a future due date is valid while a future creation date indicates inconsistent input. File captures are references, so reporting file counts cannot imply the referenced files exist.

The synthetic evidence validates the narrow assumption that a deterministic classifier can reproduce planted status/kind counts and overdue membership exactly. Corrupting record due dates changes the report; corrupting expectations does not. It does not validate daily use, personal time savings, or willingness to pay. Those assumptions remain open for the real-use window.

One operating rule for future builds: validate the entire input before replacing saved output, and simulate write failure to verify that a user's previous result survives. A named error is insufficient if it destroys the last usable artifact.
